# Negation (replies and statements) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every reply to a robot question or read-back is read as a probability over affirm, deny, unknown and none,
judged against the one statement asked. The robot code updates beliefs by Jeffrey's rule and picks act, act-against
or ask-again by cost. Told ownership keeps "not yours".

**Architecture:** Two pure headers in language_agent: `reply_reading.h` (what a reply says) and
`reply_decision.h` (what to do about it). A second, non-streaming Ollama request is the reader. `chat_session.cpp`
routes every pending question, card or confirmation through reader then decision, replacing `classify_reply` and
`fleet::is_yes`. LTOM stores fractional records, keeps ownership as told records with a polarity, and publishes
float counts. The reader prompt lives in one file read by both the agent and the eval script.

**Tech Stack:** C++23, Qt6 Core/Network, DSR (cortex), Ollama `/api/chat` with `format` (JSON schema), Python 3
eval scripts.

**Spec:** `docs/superpowers/specs/2026-11-16-negation-design.md` (on top of
`docs/superpowers/specs/2026-11-15-changed-object-design.md`)

## Global Constraints

- No thresholds. The only constants are CostAsk = 0.4 and CostWrong = 1.0 (`[Questions]` in the config).
- Use `and`/`or`/`not`, not `&&`/`||`/`!`. Parse numbers with `std::from_chars` only, and write data through
  `imbue(std::locale::classic())` or `std::format`.
- Attributes are type-attributed only. New cortex attributes go in cortex `dsr_attr_name.h`, and the **owner**
  reinstalls cortex. Never `sudo cp`.
- The model never stores a fact. Only robot code posts claims.
- Build with `-j8`, or `-j4` if another `cc1plus` is running. Stop agents with SIGTERM only. CLAIM/FREE Webots with
  the room and objects peers.
- Use the local GPU config `etc/config_local.toml` (gemma4:12b) for the reader and the eval.
- Every question the robot asks is positive.
- A question is raised at most twice, and asking again counts as the second raise.

## Review Focus

1. A reply arrives while the reader request is still running, followed by a second message: both are held and
   answered in order, and the second is never read against the closed question. Test:
   `held_while_reading` in Task 5.
2. The reader returns broken JSON, the server is down, or the request times out: the reading becomes all-none, the
   message goes to the model, and nothing is stored. Test: `parse_bad_json_is_none` (Task 1); the fallback path is
   checked in Task 5's live checklist.
3. A comma-locale machine writes or reads `yes:0.83:0.10:<stamp>`: the probabilities survive the round trip under
   `setlocale(LC_ALL, "")`. Test: `wire_round_trip_es_locale` in Task 3.
4. A memory file written before this change, with `"yes": true` records and `things` without polarity, loads with
   the same meaning. Test: `old_file_loads` in Task 3.
5. A mission card, a claim card and a fleet confirmation are pending together: only the newest takes the reply, as
   today (`newer_card_takes_the_yes`). Test: `newest_pending_takes_reply` in Task 2.

### Task 2: the decision (pure)

**Files:**
- Create: `language_agent/src/reply_decision.h`
- Test: `language_agent/tests/test_reply_decision.cpp`, added to `run_tests.sh`.

**Interfaces:**
- Consumes `Reading` and `map_label` from Task 1.
- Produces:
  - `[[nodiscard]] double jeffrey(double prior, const Reading& r);` computes
    `r.affirm + (r.unknown + r.none) * prior`.
  - `enum class Act { act_on, act_against, ask_again, unknown, pass };`
  - `[[nodiscard]] Act decide_reply(const Reading& r, double prior, bool may_ask_again, float cost_ask, float cost_wrong);`
    The rules, in order:
    - map label none → `pass`;
    - map label unknown → `unknown`;
    - otherwise `p = jeffrey(prior, r)`, and take the minimum of on = (1 − p)·cost_wrong,
      against = p·cost_wrong, and ask = cost_ask (ask only when `may_ask_again`). Ties go in the order
      on, against, ask.
  - `[[nodiscard]] double owner_moves_prior(double yes, double no);` computes `(1 + yes) / (2 + yes + no)`.
    `choose_mode` in `question_policy.h` changes to take `double yes, double no` and use it.
  - `enum class Pending { question, claim, mission, fleet };`
    `[[nodiscard]] std::optional<Pending> reply_target(std::optional<std::uint64_t> question_serial, std::optional<std::uint64_t> claim_serial, std::optional<std::uint64_t> mission_serial, std::optional<std::uint64_t> fleet_serial);`
    returns the newest pending item (largest serial) or nullopt. The moved question gets a serial from the same
    `card_serial_` counter when it is raised.
  - `[[nodiscard]] std::string reading_history_line(std::string_view robot_words, const Reading& r, Act a);`
    builds a history line, for example `(the person answered NO (p 0.86) to: "Did you move it?")`.

**Interfaces:**
- Consumes Tasks 1, 2 and 4, and Task 3's wire format.
- Produces `[[nodiscard]] std::string moved_claim_value(Act a, const Reading& r, std::uint64_t stamp);`. It writes
  `yes` for act_on, `no` for act_against and `unknown` for unknown. Probabilities have 2 decimals and go through
  `std::format`, which is locale-independent.

**The flow** (only for an algorithm the signatures leave open). In `on_user_message`, before the model:
1. `reply_target(...)` picks the newest pending item. If there is none, the existing path runs.
2. `exact_reading(text)`, or else an async `reader_.chat(...)` with `stream=false`,
   `format=reading_schema()`, temperature 0, and the statement and robot words of that pending item. While it runs,
   the message is held with the existing `held_` mechanism, and replies arriving meanwhile queue behind it. A reader
   error gives an all-none Reading.
3. `decide_reply(reading, prior, may_ask_again, CostAsk, CostWrong)`, where:
   - prior is `owner_moves_prior` for the moved question, and 0.5 for a claim, mission or fleet item;
   - `may_ask_again` is `raised < 2` for the question, and "not yet clarified" for a card or confirmation.
4. Act on the result:

   | Pending | act_on | act_against | ask_again | unknown | pass |
   |---|---|---|---|---|---|
   | question | post moved yes | post moved no | say a clarifier, `raised = 2` | post moved unknown | today's re-raise rule |
   | claim | post the claim | drop the card | say `Sorry — shall I remember that …, or not?` | drop | drop |
   | mission | start it | drop | `Sorry — shall I start it, or not?` | drop | drop |
   | fleet | `do_agent_control` | drop | `Sorry — shall I <stop/restart> <agent>, or not?` | drop | drop |

   - The question clarifier is `Sorry — did you move {the colour cls} or not?`.
   - The history gets `reading_history_line(...)`.
   - The remainder, if not empty, goes on as a user message to the model, for every act except pass.
   - On pass, the whole message goes on to the model.
